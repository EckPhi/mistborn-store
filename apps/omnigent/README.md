# Omnigent

Independent agent control plane, pinned to upstream v0.16.0 in external-runner mode. Install without Coder or MLflow. PostgreSQL contains accounts, tasks and sessions; `/data` contains operator configuration and artifacts. The server runs as UID 1000 and has no Docker socket or development filesystem mounts.

## Installation and authentication

Set the full base URL that browsers and workspace runners can reach, including scheme and port (direct host port 8097). Open the UI and create the first administrator using upstream's Create-admin form. This is intentionally an interactive first-user operation; restrict initial access to your trusted private network until completed. Accounts authentication stays enabled. PostgreSQL and cookie secrets are generated by RunTipi; retain them across upgrades. The app never resets account passwords.

## Workspace-side runner

The Coder image includes `omnigent==0.16.0` when AI tools are enabled. In a running workspace:

```sh
omnigent login https://your-omnigent-host
omnigent host --server https://your-omnigent-host --no-open
```

Run the host in tmux to survive IDE disconnects. Alternatively, use the upstream `omnigent run path/to/agent.yaml --server <url>` interface. Login stores per-server session tokens in `~/.omnigent/auth_tokens.json`; configuration and runner identity also persist in home. Register explicitly as the appropriate user. Registration is optional, and Coder remains usable without this service. Provider and Git credentials stay under the workspace user's control.

## Optional integrations

Installer Coder URL/token fields reserve `CODER_URL` and `CODER_API_TOKEN` for a future adapter. **Upstream v0.16.0 does not consume these as a native Coder provider.** Setting them alone does not create workspaces or connect runners. Use Coder API/CLI and supported SSH connectivity; do not mount Coder data or query its DB. Use a separate Coder member account with template access. See the platform guide for the experimental CLI provisioning bridge.

`MLFLOW_TRACKING_URI` is an endpoint contract, not a tracing switch. Upstream agent-plane tracing uses OpenTelemetry; configure an OTLP exporter/MLflow collector integration separately using upstream observability documentation. Do not claim that providing a URL alone enables traces. Explicit MLflow SDK logging in a workspace works independently. No observability provider is required for development.

## Privacy and operation

Upstream analytics can fetch external configuration and emit events. This app sets `OMNIGENT_ANALYTICS=0`, `OMNIGENT_DISABLE_TELEMETRY=true`, and `DO_NOT_TRACK=1`; the workspace runner inherits the same opt-outs. LLM calls still go to the user's configured provider. Content capture is not enabled. Server readiness uses `/health` after migrations and PostgreSQL readiness.

Back up `postgres/`, `server/` and installer secrets together. RunTipi's app-data backup includes both local directories; stop runners before taking a backup, and verify restoration to a disposable installation. The database and artifacts must represent a consistent point in time. Upgrades run upstream migrations; back up first, retain the database major version, and do not assume a schema downgrade is safe. Removing Omnigent must not delete Coder homes or MLflow records. Do not automatically purge task history or artifacts; review retention through supported upstream interfaces.

Troubleshooting: new chats need a connected runner; check runner login, WebSocket forwarding and TLS trust. Redirect loops usually mean an incorrect base URL. Never print installer environment files or tokens in support requests.
